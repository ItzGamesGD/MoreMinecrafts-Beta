## 0. AI가 이 문서를 읽는 규칙

### 0.1 상태 라벨 (모든 항목에 하나 이상 붙음)

| 라벨 | 의미 | AI가 할 수 있는 것 |
|---|---|---|
| `확정` | 소유자(사람)가 승인한 WHAT. 권위 문서에 기록됨 | 그대로 구현. 값 변경 금지 |
| `잠정` | 승인된 방향이지만 수치는 플레이테스트로 조정 예정 (`[PROVISIONAL]`/`[BALANCE]`) | 문서 값으로 구현, 조정은 사람 승인 후 |
| `제안` | 설계자가 낸 값, **미승인** | 승인된 값처럼 쓰면 안 됨 |
| `미정` | 결정 안 됨 (`OPEN`) | **STOP & ASK**. 임의로 채우지 말 것 |
| `보류` | 의도적으로 미룸 (`DEFERRED`/`ON HOLD`) | 구현·확장 금지 |
| `폐기` | 취소·대체됨 (`SUPERSEDED`/`CANCELLED`/`REJECTED`) | 되살리지 말 것 |
| `코드O` | 레포에 등록/구현 코드가 있음 (정적 확인) | 구현됨 ≠ 검증됨 |
| `LIVE 대기` | 실제 클라이언트 플레이 검증 안 됨 | 완료로 보고하지 말 것 |

**상태는 서로 독립이다.** `확정` + 코드 없음, `코드O` + `LIVE 대기` 같은 조합이 흔하다. "설계 확정 → 구현 → CI 통과 → LIVE 검증 → 병합"은 각각 다른 상태다.

### 0.2 권위 우선순위 (AGENTS.md 요약)

1. 사람이 WHAT을 정하고, 에이전트는 HOW만 정한다.
2. 설계 질문의 출발점은 항상 `docs/CONTENT_AUTHORITY_INDEX.md`다.
3. 같은 주제에서는 **나중에 승인된 reconciliation/override 문서**가 이전 문서를 이긴다. 단, "날짜가 최신이니 이긴다"고 스스로 추론하지 말고 인덱스가 그렇게 라우팅하는지 확인한다.
4. 기존 코드 동작은 설계 권위가 **아니다**.
5. 히스토리·체크포인트·감사·복구 문서는 맥락일 뿐, 현행 권위를 덮어쓰지 못한다.
6. 권위가 없거나, 서로 충돌하거나, 결과가 여러 갈래로 갈리면 → **STOP & ASK**.
7. 사람이 승인한 결정은 같은 작업 안에서 권위 문서에 동기화한다. 대화에만 남기지 않는다.

### 1.1 관통 원칙 (모든 축 공통)

1. **바닐라 우선.** 초반은 바닐라 플레이 그대로. 바닐라 레시피는 모두 유지된다. 지식 해금 레시피는 *추가 대안*일 뿐이다.
2. **확정 성장.** 강화·연구에 실패 확률, 하락, 파괴, 천장(pity)이 없다.
3. **독자 화폐 없음.** 코인, 토큰, 파편식 성장, 승급(Promotion)은 쓰지 않는다. 통화는 **raw XP**, **에메랄드**(바닐라 거래), **실제 재료**다.
4. **티어는 분류이지 진화 트리가 아니다.** T1→T2→T3→T4 업그레이드나 상속은 금지된다. 레시피 재료로 하위 티어 장비를 요구하는 것은 허용된다.
5. **일일 퀘스트, 리롤, 퀘스트 상점 없음.**
6. **서버 권위 + 트랜잭션.** XP, 재료, 보상 지급은 서버에서 한 번에 처리하고, 실패하면 전부 롤백한다.
7. **raw XP 정확 계산.** 레벨 대신 총 경험치 포인트로 계산한다. `setExperienceLevels` → `setExperiencePoints` → `totalExperience`를 같은 연산에서 설정하고, `giveExperiencePoints(±n)`은 쓰지 않는다.

### 4.1 T1 확장 무기 `확정` `코드O`

T1.5 같은 스킬 티어가 아니라 바닐라 무기 공간의 확장이다.

### 5.2 T1 인챈트 스킬 트리 `확정` `코드O`

출처: `T1_ENCHANTMENT_SKILL_TREE_FINALIZATION.md` — 장비별 트리 19종(검·대검·단검·도끼·곡괭이·삽·괭이·철퇴·창·삼지창·활·석궁·투구·흉갑·각반·부츠·겉날개·방패·낚싯대)

- 노드는 **실제 누적 XP**로 구매. 같은 인챈트는 순차(I→II→…). 상관없는 인챈트에 인위적 선행 조건을 만들지 않는다. 포인트 상한이 없어서 XP만 있으면 호환되는 노드를 모두 얻을 수 있다.
- 내구 가지: 내구성 I(200) → II(300) → III(500) → 수선(1,000). 합계 2,000.
- 비용 등급: Minor 100 / Standard 200 / Major 400 / Capstone 800+ (비율 약 1:2:4:8).
- 5레벨 곡선: 100/150/200/300/400 = 1,150.
- 커스텀 기능 노드: 광맥 채굴 I ~500, II ~800 / 나무꾼·자동 심기 500–800 / 깃털 부츠·겉날개 발사 800–1,000.
- 호환성:
  - **자유 중첩**: 수선+무한, 석궁 관통+다중 발사, 차가운 걸음+물갈퀴.
  - **프리미엄 중첩**: 날카로움+강타 같은 고위력 중복. 보호 계열은 두 번째 +500, 세 번째 +1,000, 네 번째 +2,000.
  - **구조적 배제**: 활 Multi Shot ↔ Laser Arrow, 석궁 Crossbow Barrage ↔ Multishot.

### 5.3 책 옵션(Book Option)과 주민 거래 `확정`

출처: `VILLAGER_TRADE_AND_ENCHANTED_BOOK_INTEGRATION_CHECKPOINT.md`

- 인챈트 책 + 모루로 인챈트를 적용하던 경로는 `폐기`. 책은 트리의 인챈트를 대신하거나 건너뛰지 못한다.
- 책 옵션 = 기존 인챈트 효과 **위에 얹는 보너스**. 예: 수선 XP당 수리 2 → 4.
- 옵션의 최대 레벨 = 해당 인챈트의 바닐라 최대 레벨 (날카로움 +I~+V, 보호 +I~+IV, 수선 +I). 표시 예: `Sharpness V (+IV)`.
- 책 레벨이 높을수록 높은 옵션이 나올 확률이 오르지만(이항 분포 규칙), 책 레벨이 상한이 되지는 않는다. 한 번 적용하면 비싼 리셋 전까지 고정. 옵션끼리 슬롯을 다투지 않는다.
- 책 옵션 없이도 장비는 '완성'으로 느껴져야 한다.

### 5.4 룬 `확정`(문서만)

출처: `RARE_CARAVAN_ENCHANTMENT_RUNE_DECISIONS_2026-10-18.md`

- 룬은 바닐라 인챈트 책의 역할을 하는 *실제 인챈트 적용* 아이템이다. 인챈트 테이블 상한을 넘는 승인된 레벨만 판매한다(24개 SKU). 예: 날카로움 VI.
- 융합 없음, 하위 레벨 선행 없음. 높은 레벨이 있으면 하위 레벨은 완료된 것으로 표시.
- 판매처는 최상급 희귀 교역단뿐이고 4종이 무작위로 나온다(§14.2).

## 15. 새 콘텐츠·새 축을 설계할 때의 규칙 (권위에서 유도한 것만)

1. **새 축은 기본 보류다.** `CONTENT_AUTHORITY_INDEX.md`의 "Idea parking lot"에 따라 새 독립 축(새 경제, 새 진행 체계 등)은 사람이 명시적으로 선택하기 전까지 아이디어 수준으로만 보존한다. AI가 상세 설계로 키우지 않는다.
2. **WHAT은 사람만 정한다.** AI는 선택지와 장단점을 제시하고, 승인된 것만 권위 문서에 기록한다(제안·논의는 승격하지 않음).
3. 사용자는 **한 번에 의미 있는 결정 하나**를 묻는 방식을 선호한다. 이미 확정된 값을 다시 묻거나 바꾸지 않는다.
4. **모든 설계가 끝나기 전에는 최종 구현 지시문을 쓰지 않는다**(하늘섬·T2 문서 §7).
5. 기존 규칙과 충돌하지 않는지 먼저 확인한다.
   - 장비라면 티어를 지정하고, 티어 간 진화는 금지.
   - T2라면 무한 내구도, 우클릭 액티브, 이더리움 공통 재료, 코어 첫 획득 시 레시피 해금.
   - 성장이라면 확정 성장과 raw XP 트랜잭션.
   - 경제라면 독자 화폐·일일 퀘스트·상점 없음.
   - 낚시라면 4필드 데이터 모델을 공유.
   - 몹이라면 40종 로스터와 겹치지 않고, 일반 몹은 바닐라 모델 재사용.
6. **보스 → 보상 정체 → 희귀 재료 → T3/T4 레시피** 순서를 지킨다.
7. 희귀 재료의 공급과 소비를 함께 설계한다(깃털처럼 공급만 늘리지 않기).
8. 이름, 확률, 수량을 정하지 않았으면 `미정`으로 남긴다. 추측한 루트 테이블을 넣지 않는다.
