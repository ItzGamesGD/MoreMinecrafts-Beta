## 1. Root researches: seven independent skill trees
Every discipline has one single-level paid root. The root must be purchased before any other research in that discipline. Roots never require another discipline root. Each root is eligible if the player has unlocked **any one** free knowledge entry assigned to that discipline; no arbitrary one-specific-knowledge gate. Existing root knowledge eligibility (#31 combat / #41 ecology as examples) remains included, not exclusive.

| discipline id | root id | effect, applied once | cost (raw XP + items) |
|---|---|---|---|
| resources | resources_root | +1% XP from eligible ore mining XP orbs (fractional remainder accumulated per player, no XP from blocks with no XP) | 80 XP + cobblestone 16 + coal 16 |
| production | production_root | +1% XP from eligible smelting XP (fractional remainder accumulated) | 80 XP + furnace 16 + iron ingot 16 |
| living | living_root | +1% crop random-growth probability per eligible random tick; never force growth or affect bonemeal | 80 XP + wheat seeds 16 + wheat 16 |
| combat | combat_root | +1% damage to hostile mobs (existing) | 80 XP + stick 16 + bone 16 (existing) |
| ecology | ecology_root | +1% hostile mob XP orb yield (existing) | 80 XP + rotten flesh 16 + bone 16 (existing) |
| world | world_root | +1% base walking movement speed while on ground, as a named additive attribute modifier; not elytra, riding, boat or sprint multiplier | 80 XP + compass 16 + paper 16 |
| alchemy | alchemy_root | +1% duration of beneficial timed potion effects from potions used by the researcher; rounded to ticks, never increases amplifier or instant effects | 80 XP + glass bottle 16 + nether wart 16 |

One-time purchase only. Root bonuses never recursively trigger each other, never grant XP for a zero-XP event, and do not create an additional paid level for existing research. Root price and materials are separately charged once. Existing 87 nodes/195 purchases/147,270 raw XP become **92 nodes/200 purchases/147,670 raw XP**, assuming no other additions. Root names in UI use existing discipline display names; internal world discipline id remains `world` (do not rename saved IDs).

**Existing saves:** on first load after migration, for each discipline in which a player already owns ANY paid research, grant that discipline's root as a **free grandfathered entitlement**, without deducting XP/materials, without re-awarding existing research, and persist the grant idempotently. A new player must purchase the root. Knowledge discoveries and previous research levels remain untouched.

## 3. Counter-shield shaped recipe
Exactly vanilla shield shape, replacing every wooden plank with an iron ingot and its top-center iron ingot with obsidian:
```
iron_ingot | obsidian   | iron_ingot
iron_ingot | iron_ingot | iron_ingot
empty      | iron_ingot | empty
```
Output ONE counter-shield. Six iron ingots + one obsidian. No intermediate shield tier. Preserve previously approved knockback effect and cooldown.

## 4. Motorized boat
The engine is a single crafted attachable upgrade, not a new separate boat inventory. Craft 1 engine from iron ingots 4, copper ingots 2, redstone dust 2, furnace 1, shapeless (one unit). Attach by right-clicking a normal boat with engine in hand; consumes one engine and preserves the boat's type and occupants safely. Do not attach twice. When broken, return the normal boat and engine separately, once. Fuel slot UI opens with Shift+right-click as approved; fuel: coal = 8 fuel units, charcoal = 8, coal block = 72. Fuel storage cap 576 units; one fuel unit lasts 20 seconds at speed setting 5; fractional consumption persisted. Speed setting by selected hotbar slot 1–9; multipliers [0.50,0.625,0.75,0.875,1.0,1.25,1.5,1.75,2.0] relative to unmodified vanilla boat cruising speed. Consumption is linear in multiplier, not squared; no movement means no fuel consumption. At zero fuel, boat moves at ordinary vanilla speed without powered bonus. Existing Navigation research applies its bonus without extra fuel. Boat and fuel persist on chunk unload/server restart. Server authoritative; no fuel duplication on break, drop or dismount.

## 5. Cross-dimensional home item transport
Unlock a bound sender item plus a receiving chest/block at player's current respawn bed/home anchor. The receiver is explicit: right-click receiver to bind to owning player's UUID and current dimension/position; bed respawn is a suggested location, not a substitute for a physically placed receiver. Sender UI chooses only the owner's bound receiver, and selects exact inventory stacks to send. **No implicit sending to inventory, no forced chunk loading.** Only send when the receiver exists and is owned by sender. Transaction: reserve and remove selected source items once into a durable server-side queue with unique delivery id; acknowledge to client only after durable commit. A delivery attempt moves items exactly once into receiver inventory, with persisted receipt/commit state and crash-safe recovery. If receiver is unloaded/full/destroyed/ownership invalid, items remain in durable queue (not dropped, not lost), and player can cancel to return to a durable recovery mailbox only after confirming undelivered status. A mailbox can be opened from the sender UI; its contents are claimed into inventory when space permits. No expiry; no cross-player access; prevent double claim and replay. Visual flying item is cosmetic only in loaded chunks. If transactional durability and restart tests cannot be proven, feature remains disabled, not partially released.

## 6. One brewing mixing/concentration UI
Use ONE MIXING/CONCENTRATION tab in the approved extended vanilla brewing UI. Two input finished potions per operation; supports splash, lingering, and drinkable only when both have the same delivery type; no whitelist or prohibition based on effect combinations. Each input may contain multiple effects; union effects up to **four distinct effects** per resulting potion. If both inputs have the **same effect set AND matching amplifier for each effect**, treat as CONCENTRATION: increase each eligible non-instant effect amplifier by one, once only, obey vanilla effect-specific absolute caps and existing special Bad Omen cap V. Instant effects are not amplifier-boosted; reject concentration if no effect can be increased. For other combinations, MIX: combine effect sets, preserving each effect's stronger amplifier; for identical effects with unequal amplifiers use the stronger amplifier, duration = max(original durations)×0.70; for nonoverlapping effects each duration×0.70. Concentration duration = min(input duration per effect)×0.70. Both consume two input bottles and one nether wart plus one glowstone dust as process ingredients. Output one finished potion, with empty bottle remainder handled without dupe (one empty bottle returned, other bottle embodied in output). Insufficient output space blocks transaction. All effects including harmful combinations allowed; no compatibility whitelist. If result has >4 effects, reject with nonconsuming error. Effect caps/instant mechanics must be checked against actual registry and existing authority; no invented beyond-vanilla level escalation beyond previously approved one-step concentration.

## 7. Ecology research and custom mobs
All applicable research and knowledge mob-family effects apply to MoreMinecrafts custom mobs via explicit, versioned entity tags/classification. A mob may have multiple tags, but the same effect family (including +5% free-knowledge damage) applies at most once to that mob; do not stack duplicate taxonomy hits. Bosses follow boss-specific exclusion rules, rare-mob rules follow actual rare tags; no implicit vanilla-only whitelist. Audit the current 40 custom mobs against family tags before implementation. Unclassified mobs do not receive a guessed family bonus; add verified mapping first.

## 8. Automation devices: remaining delegated edge behavior
Common transaction rules: server authority, atomic input/output commit, no chunk force-loading, persist progress and exact fuel/item state, no simulation while unloaded unless existing authority explicitly permits, never delete or duplicate items, avoid unsolicited inventory scans outside device scope. On blocked output, **pause without consuming inputs/fuel or generating outputs**; on restart, resume only persisted valid work. Redstone toggles are edge-triggered where toggles are specified, and level-triggered only for explicit sustained-mode controls.

- **Auto Farm:** preserve approved 9×9 area, separate seeds and produce; never uproot invalid/immature crops. Handle vanilla crops via explicit registered harvesting/replant rules; unknown modded crops skipped safely. When seed/output storage lacks space for a complete harvest-and-replant transaction, skip that crop. Harvest only loaded chunks and only owned/allowed area. Hopper bottom extracts finished produce only. Preserve redstone mode on reload; no progress catch-up across unload.
- **Auto Lumber:** preserve 1×1 device, one-log-per-work-step visual breaks, 4-tick initial cadence, fuel 1 coal per 8 logs, tool wear 1 per 3 logs. Identify connected natural tree logs using bounded queue and leaves/proximity heuristic; player structures with no matching leaves are skipped; protected/unloaded logs skipped. Drops in place immediately above device. Persist queue cursor, accumulated fractional fuel/tool costs and consumed block IDs; revalidate before each break. If drop location cannot safely accept items, pause.
- **Chest Sorting:** in-place stable sorting, no item creation or deletion; default precedence = tools/equipment, materials/blocks, food/farming, potions/consumables, miscellaneous; within category namespace+item ID lexicographic, then damage/components identity, stable original slot order. Never merge stacks with different data components; never touch player inventory; if an inventory mutation occurs during operation, abort and retry from fresh snapshot.
- **Hopper Filter:** one compact side panel for whitelist/blacklist with up to 9 exact item identity entries; default whitelist mode with zero entries = pass nothing, blacklist mode with zero entries = pass all. Filter applies to both hopper push and pull; configured ghost entries do not consume items. Item component-sensitive exact matching is optional per entry, default item type only. Persist rules per hopper; preserve vanilla transfer timing and no hidden throughput boost.
- **Brewing Process Control:** preserve approved 9 waiting-material slots and 9 finished-output slots, vanilla intermediate recipe steps, ON/OFF, hopper inputs, finished-only bottom extraction. Reserve only actual materials for the next brew step; no partial output consumption on full slots. If ingredient, fuel, or output unavailable, pause without discarding in-progress potion state. Restart resumes only persisted transaction stage; disable and rollback reservations safely on block break. Mixing/concentration follows section 6 and shares the brewing UI without bypassing output constraints.
