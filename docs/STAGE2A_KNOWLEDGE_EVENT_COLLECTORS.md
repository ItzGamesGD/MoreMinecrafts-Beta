# Stage 2-A Knowledge collector implementation status

This corrective pass adds provenance for completed/collected furnace and brewing outputs and a centralized first-unlock chat notification. Progress remains in the existing persistent `ResearchProgressState` attachment; its existing condition update path unlocks entries and syncs deltas. K59 remains an item-count condition (10 actual spawned items); K70 remains a cumulative item-count condition (5 registered `strong_*` potion items). K70's existing enum label remains unchanged to preserve the approved node-tree manifest and catalog consistency; runtime collection semantics remain cumulative item count.

Status reflects evidence available at this commit: **IMPLEMENTED_NOT_VERIFIED** means a runtime hook is present, but compilation and actual hook execution have not yet been demonstrated. The local Gradle process cannot start in this environment because wildcard network-interface enumeration fails with `SocketException: Operation not permitted`.

Their reward consumers are still absent, so none is promoted to implementation class A by this work. K51 remains Stage 1 class F and unresolved; it is not modified.

## Tests and evidence

- `KnowledgeEventRulesTest` covers ore-family normalization, non-ore exclusion, registered strengthened versus ordinary potion distinction, unique potion IDs, and approved versus ordinary ammunition identification.
- These are predicate tests only. They do not establish runtime mixin application or prove that an action reached a hook in a running server.
- The unlock announcement is emitted only on the locked-to-unlocked transition at `grantKnowledge`, styles the catalog's translated title green, uses the vanilla advancement announcement gamerule, and derives first-unlock guidance from existing Knowledge attachment state. Join-time stat/exploration reconciliation is silenced to avoid announcement backlogs. Guidance resolves the configured `key.advancements` binding.
- Action-level GameTests for all eleven hooks, multiplayer announcement recipients/gamerule behavior, and translation presentation are still outstanding. Do not report those hooks as `VERIFIED_RUNTIME`.
- Full project validation (`./gradlew clean test build compileGametestJava runGameTest`) could not start locally: Gradle was denied wildcard socket enumeration (`Could not determine a usable wildcard IP`). Use PR CI for build/test evidence; compilation alone does not establish live action-hook behavior.
