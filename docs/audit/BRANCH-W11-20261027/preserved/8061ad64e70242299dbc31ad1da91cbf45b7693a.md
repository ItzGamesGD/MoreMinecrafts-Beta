# MoreMinecrafts — Structure: Ancient City Expansion Decisions (2026-10-13)

> 상태: 사용자 승인 설계 기록. **구현 자체는 아직 시작하지 않음.**
> 활성 설계 계보: `docs/2026-10-07-content-first-axis-review`.
> 이 문서는 기존 연구/지식 설계를 대체하지 않고, Structure 트랙의 고대도시 확장 결정을 별도로 기록한다.

## 1. 기본 방향

- 고대도시 확장은 신규 퍼즐·게이지·복잡한 전용 기믹을 추가하는 방식보다 **구조물과 몹, 기존 월드젠 요소의 변형·조작·재조합**을 우선한다.
- 바닐라 고대도시의 워든/소리 플레이의 무게감은 유지한다.
- 현재 초안에서 워든은 기본적으로 싸워서 해결하는 보스가 아니라 **피해야 하는 존재**로 취급한다.
- 전초기지에서 얻는 특정 염소 뿔나팔과 워든의 상호작용 아이디어는 사용자 별도 구상으로 존재하나, 세부안이 제시되기 전까지 임의 설계/구현하지 않는다.
- 기존 T2 대지 핵심 아이템 **고대의 심장** 획득 경로를 임의 변경하지 않는다.

## 2. 구조 체계 — 확정

고대도시 확장을 두 계층으로 분리한다.

### A. 독립 고대도시 구조물

도시 전체 테마와 별개로 일반 고대도시에도 추가될 수 있는 개별 랜드마크/구조물이다.

#### 고대도시 경기장 / 콜로세움 — 첫 시안 대상

- 고대도시 건축 양식과 어울리는 대형 원형 또는 콜로세움형 경기장.
- 심층암 벽돌 등 기존 고대도시 계열 블록 팔레트를 적극 재사용한다.
- 중앙 경기장과 주변 관람/벽체 구조가 직관적으로 읽히는 형태를 목표로 한다.
- 세부 블록 배치, 파손 정도, 스컬크 배치, 크기와 구조 조합은 **첫 프로토타입 제작자에게 재량을 허용**한다.
- 신규 퍼즐/UI/퀘스트/진행 게이트를 붙이지 않는다. 구조물 자체가 콘텐츠다.

### B. 도시 전체 변형 (Whole-city Variants)

고대도시 전체의 상태와 분위기를 바꾸는 별도 변형 계층이다. 독립 구조물과 분리한다.

현재 채택된 콘셉트:

1. **죽음/잔해 고대도시**
   - 스컬크가 주변 몹의 죽음에서 확산된다는 설정에서 출발.
   - "이 정도의 스컬크가 존재하려면 대체 얼마나 많은 생명이 죽었는가?"라는 괴담성 발상을 환경 서사로 구체화한다.
   - 죽은 몹의 흔적, 잔해, 파괴 흔적 등이 도시 곳곳에 존재하는 방향.

2. **네더 침식 고대도시**
   - 고대도시 중앙의 워든 형상 구조물 내부 사각형에 네더 포탈이 열린 상태를 핵심 이미지로 한다.
   - 중앙 구조물로부터 네더화가 확산된 듯한 블록 변형.
   - 구조물 일부가 네더 테마로 침식되고 네더 몹이 도시를 돌아다니는 방향.

3. **전성기의 고대도시**
   - 폐허가 되기 전, 실제로 살아 있던 고대도시를 표현.
   - 기존 고대도시 구조 모듈을 분석해 파손/폐허 요소를 복구·수정하는 접근을 우선 검토한다.
   - 고대도시 주민이 생활한다.
   - 워든은 적대적 괴물이 아니라 철 골렘과 비슷한 도시 수호자 역할의 친화적 존재로 돌아다니는 콘셉트.
   - 실제 주민 AI, 워든 행동 변경 등은 구현 조사 전까지 세부 확정하지 않는다.

## 3. 생성 관계

- **경기장 등 독립 구조물**은 도시 전체 변형과 별개로 취급한다.
- **죽음 / 네더 침식 / 전성기**는 도시 전체의 테마를 결정하는 변형이다.
- 따라서 향후 도시 변형 종류가 늘어나더라도 독립 구조물 목록과 도시 변형 목록을 분리해 확장할 수 있어야 한다.
- 구체적인 생성 확률과 조합 가능 여부는 구현/월드젠 조사 후 조정한다.

## 4. 첫 구현 프로토타입 승인 범위

다음 작업의 첫 프로토타입은 **고대도시 경기장 하나만** 대상으로 한다.

목표:
1. 실제 대상 Minecraft/Fabric 버전의 바닐라 고대도시 생성 코드·데이터·구조 풀을 조사한다.
2. 경기장 시안 하나를 제작한다.
3. 가능한 한 비침습적인 방식으로 고대도시 Structure 생성 체계에 편입한다.
4. 모든 고대도시에 강제 생성하지 않고 **랜덤하게 등장 가능한 경로**를 만든다.
5. 코드/리소스 정적 검증뿐 아니라 랜덤 선택 가능성을 테스트한다.
6. 환경이 허용하면 실제 월드젠에서 경기장이 포함된 고대도시와 일반 고대도시가 모두 생성됨을 검증한다.
7. 기존 GitHub Actions/Xvfb 클라이언트 캡처 인프라를 재사용할 수 있다면 실제 생성 결과의 시각 검증까지 수행한다.

프로토타입의 생성 가중치/확률은 구현자가 합리적인 임시값을 선택해도 되지만 반드시 문서화하고 추후 밸런스 조정 가능하게 만든다.

## 5. 프로토타입 비범위

첫 경기장 프로토타입에서 다음은 구현하지 않는다.

- 죽음/잔해 도시 전체 변형
- 네더 침식 도시 전체 변형
- 전성기 도시 전체 변형
- 워든 AI 재설계
- 염소 뿔나팔-워든 상호작용
- 신규 연구/지식 노드
- 고대의 심장 획득 경로 재설계
- 신규 복잡 퍼즐/게이지/UI/퀘스트 시스템
- 관련 없는 구조물 또는 게임플레이 수정

## 6. 검증 원칙

등록만 되어 있다는 이유로 월드젠 성공으로 판정하지 않는다.

프로토타입 완료 보고는 가능한 범위에서 다음 상태를 분리한다.

- `IMPLEMENTED`
- `STATICALLY VERIFIED`
- `RUNTIME VERIFIED`
- `WORLDGEN VERIFIED`
- `VISUALLY VERIFIED`

실행 환경 제약으로 실제 월드젠/캡처를 검증하지 못했다면 이를 성공으로 추정하지 않고 정확히 미검증 상태로 남긴다.

## 7. 계보 / 권위

- 기존 권위 문서의 미변경 조항은 유지한다.
- 구현 시작 전 현재 원격 HEAD, 최신 checkpoint, 관련 PR 및 권위 문서를 다시 검증한다.
