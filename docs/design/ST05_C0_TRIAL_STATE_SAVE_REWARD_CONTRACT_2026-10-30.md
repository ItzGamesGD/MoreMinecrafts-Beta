불변식 I-ID2: 소유 태그의 값이 컨트롤러 기록의 ALIVE 할당 `(trialId, round, index, entityUuid)`와 정확히 일치하지 않는 엔티티는 시험 소유가 아니다(고아).

## 4. 상태 머신

### 4.1 단계(phase)와 독립 플래그

단계: `READY → ROUND(r) → INTERMISSION(r) → … → BOSS → SUCCESS | FAILURE → COOLDOWN → READY`.  
`SUCCESS`와 `FAILURE`는 같은 틱 안에서 정리와 기록을 마치고 `COOLDOWN`으로 넘어가는 일시 단계다.

단계와 독립적으로 관리하는 값:

- `paused`: 부재 일시정지. `absenceTicks > 0`으로 판단.
- `spawnBlocked`와 `blockedTicks`: Q110 차단 시계.
- `bossStarted`: R7 핸들러가 보스를 생성했는지.

### 4.2 전이표

틱 판정 순서: ① ALIVE 할당 재확인(§6.3) → ② 전멸 판정 → ③ 부재 판정 → ④ 단계별 진행.

| # | 현재 | 조건 | 다음 | 부수 효과 |
|---|---|---|---|---|
| T1 | READY | 적격 플레이어가 중심 활성 반경 안 | ROUND(1) | `trialId` 발급, `trialSerial++`, 파란 입자, 구역 안 플레이어를 R1 참가자로 잠금 |
| T2 | ROUND(r) | 모든 할당이 KILLED이고 미정지 | INTERMISSION(r) | 웨이브 기록 1회(§9), 사망 제외 해제, r=3·5면 보급 상자 생성 요청 |
| T3 | INTERMISSION(r), r<6 | 휴식 잔여 0이고 미정지 | ROUND(r+1) | 그 시점 구역 안 플레이어로 재잠금하고 예산 산정 |
| T4 | INTERMISSION(6) | 휴식 잔여 0이고 미정지 | BOSS | R7 참가자 잠금, `bossStarted=false` |
| T5 | BOSS | `bossStarted=false` | BOSS | 매 틱 보스 핸들러 시작 시도. 핸들러가 없으면 대기(가짜 성공 금지) |
| T6 | BOSS | 보스 핸들러가 처치를 보고(`trialId` 일치, `bossStarted`) | SUCCESS → COOLDOWN | 보급 정리, 쿨다운 78,000 |
| T7 | ROUND/BOSS | 이번 라운드 잠금 참가자 전원 사망 | FAILURE → COOLDOWN | 시험 몹·보스·보급 정리(전리품·XP 없음), 열쇠 회수 없음 |
| T8 | ROUND/INTERMISSION/BOSS | `absenceTicks` ≥ 1,200 | FAILURE → COOLDOWN | T7과 같음 |
| T9 | ROUND | `blockedTicks` ≥ 1,200이고 새로 확인해도 여전히 차단 | FAILURE → COOLDOWN | T7과 같음 |
| T10 | ROUND(r) | 편성 불가(활성 풀이 비었거나 쓸 수 없음) | FAILURE → COOLDOWN | 데이터 검증 실패로 기록 |
| T11 | 활성 단계 | 운영자나 통합 코드가 강제 초기화 | FAILURE → COOLDOWN | T7과 같음 |
| T12 | COOLDOWN | 잔여 0 | READY | — |

부재 판정: ROUND·BOSS에서는 "이번 라운드 잠금 참가자 중 사망 제외가 아닌 사람이 구역 안에 있는지", INTERMISSION에서는 "적격 플레이어가 구역 안에 있는지"를 본다. 없으면 `absenceTicks++` 후 이번 틱 진행을 멈추고, 있으면 0으로 되돌린다. 부재 중에도 기존 몹의 AI는 그대로 동작한다(Q101).

### 4.3 불변식

- **I1** 동시 생존 시험 몹 ≤ 12. 경고 중인 것도 정원에 포함한다.
- **I2** 할당 상태는 PENDING / WARNING / ALIVE / KILLED 중 정확히 하나이고, 모두 합하면 할당 총수다. 라운드 도중 할당은 늘거나 줄지 않는다.
- **I3** KILLED로 바뀔 수 있는 것은 ALIVE뿐이다. KILLED는 되돌릴 수 없다.
- **I4** 한 `(trialId, round)`의 웨이브 기록과 공유 열쇠 발급은 많아야 1회다.
- **I5** 소유 태그가 없는 엔티티는 예산, 집계, 정리, 진행 어디에도 영향을 주지 않는다.
- **I6** 위치 확인 실패는 할당을 소모하지 않는다.
- **I7** 정지 중에는 라운드 완료, 휴식 진행, 새 소환 배치가 없다.
- **I8** 보상 장부(§9)는 시험 종료, 실패, 초기화, 다음 시험 시작으로 삭제되지 않는다.
- **I9** 컨트롤러는 Vault 블록 엔티티 상태를 읽거나 쓰지 않는다.

## 6. 몬스터 할당·소유권·유효 처치

### 6.1 편성

권위 그대로 따른다: 활성 15종만, 예산 `round(solo × (1 + 0.6(n−1)))`, 점수 상한 4/7/10, 85–100% → 105% → 예산 이하 최대치 순서. R3는 정예 정확히 1체와 근접·원거리·특수 역할 포괄. 선호 가중치는 잠정값이며 밸런스 작업 대상이다.

### 6.2 소환

- 소환 주기는 1초다.
- 생존 + 경고가 6 이하이고 대기 할당이 있으면 12까지 경고를 건다.
- 위치는 12–24 고리 안에서 고르고, 경고 약 1초 뒤 위치를 다시 검사한 다음 생성한다.
- 생성 직전에 할당을 ALIVE로 묶은 뒤 월드에 추가한다. 그래야 소유 검증이 자기 자신을 거부하지 않는다.
- 추가에 실패하면 PENDING으로 되돌린다.

### 6.3 생존 재확인

ALIVE 할당마다 엔티티 UUID와 마지막 청크를 확인한다.

| 확인 결과 | 처리 |
|---|---|
| 엔티티 있음 | 청크 갱신 |
| 엔티티 없음, 청크의 엔티티가 로드됨 | GONE → §6.4 |
| 엔티티 없음, 청크 미로드 | 유지(중복 소환 금지) |

### 6.4 Q111 — 미인정 사망·소실의 재소환

다음은 모두 해당 할당을 PENDING으로 되돌려 다음 정상 배치에서 다시 소환한다. 카운트는 늘지 않고 `requeues`만 증가한다.

| 사건 | 판정 |
|---|---|
| 처치 판정 순간 구역 안에 적격 플레이어가 없음 | 미인정 사망 → 재소환 |
| 디스폰·`discard`(평화로움 포함)·차원 이동 | 소실 → 재소환 |
| 재시작 후 기록 청크는 로드됐는데 엔티티가 없음 | 소실 → 재소환 |
| 변환(예: 좀비 → 드라운드) | 원본 소실 → 재소환. 변환된 몹은 외부 몹 |
| 청크 언로드(UNLOADED_*) | 소실 아님 → ALIVE 유지 |

재소환 횟수 상한은 권위에 없다. 무한 반복을 막는 장치는 기존 규칙(부재 60초, Q110)뿐이다(§13 R-1).

## 7. 시간 관리 — 남은 온라인 시간

- 모든 시간 값은 **남은 틱 수**로 저장한다: `intermissionRemaining`, `absenceTicks`, `blockedTicks`, `batchTimer`, `cooldownRemaining`, 경고 `warningTicks`.
- 시계는 서버가 해당 차원을 틱할 때만 1씩 움직인다. 서버가 꺼져 있거나 일시정지된 시간(예: 빈 서버 일시정지 `pause-when-empty-seconds`)은 소모되지 않는다. 이것이 "온라인 시간" 기준이다.
- 컨트롤러는 아레나 청크가 로드되지 않아도 매 틱 돈다. 그래서 부재 유예와 쿨다운은 멀리 떠난 플레이어에게도 정상적으로 만료된다.
- 벽시계(`System.currentTimeMillis`)나 `gameTime` 차이는 판정에 쓰지 않는다. `gameTime`은 기록용 타임스탬프로만 쓴다.

## 8. 저장 데이터 스키마와 복구

### 8.1 위치

차원별 `SavedData`, id `moreminecrafts:st05_colosseum_arenas`, `DataFixTypes.LEVEL`.

### 8.2 스키마 v1

```text
root {
  schema: int = 1
  arenas: [ArenaRecord]
}
ArenaRecord {
  instance_id: string                 # structureInstanceId
  geometry: { center, combat_radius, min_y, max_y, activation_radius, spawn_min_y, spawn_max_y }
  trial: TrialState
  ledger: RewardLedger                # §9, 영구 보존
}
TrialState {
  core:    { phase, last_outcome, trial?, last_trial?, serial, seed, round }
  timers:  { intermission, absence, spawn_blocked_ticks, spawn_blocked, batch_timer, cooldown, boss_started }
  party:   { locked:[uuid], dead:[uuid], ever:[uuid] }
  content: { allocations:[Allocation], supplies:[long] }
}
Allocation { index, mob(enum name), focal, status, entity?, chunk, warning_pos, warning_ticks, requeues }
RewardLedger {
  waves:       [WaveRecord]           # (trial, round) 유일
  eligibility: [EligibilityRecord]    # (trial, round, player) 유일
  claims:      [ClaimRecord]          # (trial, round, player, reward) 유일
}
WaveRecord        { trial, serial, round, locked:[uuid], present_at_clear:[uuid], cleared_game_time, shared_key: NONE|ISSUED, key_game_time? }
EligibilityRecord { trial, round, player, basis }
ClaimRecord       { trial, round, player, reward_id, claimed_game_time }
```

enum 값은 이름 문자열로 저장한다(순서 의존 없음). enum 이름을 바꾸려면 마이그레이션이 필요하다.

### 8.3 버전 관리

| 읽은 `schema` | 처리 |
|---|---|
| 없음 | v0(#213의 무버전 형식). `instance_id = test|<dim>|<center>`, 빈 장부로 읽고 기존 `cleared_waves`를 `ledger.waves`로 옮김 |
| 1 | 그대로 |
| > 1 (미래 버전) | **읽기 전용 보존 모드**: 해당 아레나를 틱하지 않고, 원본 NBT를 그대로 다시 쓰고, 오류 로그를 남김. 기록 삭제 금지 |

### 8.4 저장 순서와 원자성

- 컨트롤러 상태와 장부는 같은 `SavedData` 안에서 같은 틱에 바뀌고, 바뀔 때마다 `setDirty` 한다.
- 엔티티(시험 몹, 공유 열쇠 아이템)는 청크 저장에 들어간다. 정상 종료와 자동 저장은 둘 다 기록하지만 두 저장이 원자적이지는 않다.
- 그래서 각 위험을 아래 방식으로 막는다.

| 위험 | 대응 |
|---|---|
| 상태는 WARNING인데 엔티티가 이미 저장됨(크래시) | 재시작 후 그 엔티티는 소유 검증에서 거부(고아). 경고가 끝나면 1회만 생성 |
| 상태는 ALIVE인데 엔티티가 저장되지 않음 | GONE 판정 → 재소환(§6.4) |
| 처치는 저장됐는데 죽어 가던 엔티티가 저장됨 | 로드 시 할당이 KILLED이므로 거부 |
| 열쇠 기록은 ISSUED인데 아이템이 저장되지 않음 | **최대 1회** 정책. 재발급하지 않는다(I4). 크래시 시 손실 가능 → §13 R-2 |

"정확한 복원"(Q112)의 범위: 단계, 라운드, 참가자, 모든 할당 상태와 엔티티 ID, 경고 위치와 남은 틱, 모든 타이머, 장부. 몹의 위치·체력·AI 목표는 바닐라 엔티티 저장에 따른다.

### 8.5 복구 절차(서버 시작 시)

1. 스키마를 읽고 §8.3에 따라 버전을 처리한다.
2. 일시 단계(SUCCESS·FAILURE)가 남아 있으면 정리를 마치고 COOLDOWN으로 만든다.
3. ALIVE 할당은 그대로 두고, 청크 엔티티 로드가 존재/부재를 증명할 때까지 기다린다.
4. WARNING은 남은 틱부터 이어 간다.
5. 엔티티가 로드될 때마다 소유 검증으로 고아를 거부한다(I-ID2).
6. 장부는 읽기만 한다. 복구 과정이 장부에 쓰는 일은 없다.
7. BOSS 단계에서 `bossStarted=true`면 보스 핸들러에 재개 알림을 보낸다(재생성 여부는 핸들러 책임).

참가자는 다시 접속해야 존재가 회복된다. 접속 전에는 부재 시계가 흐른다.

## 9. 보상 계약(Q113, Q51, Q97)

### 9.1 공유 Trial Key

- 라운드 r(1–6)이 처음 완료되면 `WaveRecord(trial, r)`를 만든다.
- 같은 틱에 `shared_key = ISSUED`로 기록한 직후, 정확한 중심에 일반 Trial Key 1개를 평범한 `ItemEntity`로 생성한다.
- 이미 ISSUED면 아무것도 하지 않는다.
- 열쇠 `ItemStack`에는 **컴포넌트를 추가하지 않는다**. Minecraft 26.3 `VaultBlockEntity.isValidToInsert`가 `ItemStack.isSameItemSameComponents`로 열쇠를 대조하는 것을 바이트코드로 확인했다. 따라서 표식 컴포넌트를 달면 Vault가 그 열쇠를 거부하고, 일반 열쇠와도 겹쳐지지 않는다. 추적이 필요하면 아이템 엔티티 attachment(줍기 전까지만 유지)를 쓴다.
- 실패·초기화 시 열쇠를 회수하거나 정리하지 않는다. 바닥의 열쇠는 바닐라 디스폰·줍기 규칙을 따른다(Q97).
- R7 Ominous Trial Key는 보스 발밑 드롭이며 보스 단계(C5)의 책임이다. 웨이브 장부와 별개다.

### 9.2 개인별 자격과 수령 이력(공유 열쇠와 분리)

- 자격 기록 `EligibilityRecord`와 수령 기록 `ClaimRecord`는 공유 열쇠 발급 여부와 독립된 별도 목록이다.
- 공유 열쇠는 플레이어 수와 관계없이 웨이브당 1개다. 자격 기록이 열쇠를 늘리지 않는다.
- `(trial, round, player)`당 자격은 1건, `(trial, round, player, reward)`당 수령은 1건이다. 중복 지급 방지는 "수령 기록이 이미 있으면 거부"로 판정한다.
- 자격 판정 기준(`basis`)은 **미결**(O-2). 후보:
  - (a) 라운드 시작 잠금 참가자
  - (b) 클리어 순간 구역 안 존재자
  - (c) (a)와 (b)의 교집합
  - (d) (a)이면서 이번 라운드 사망 제외가 아님

  권위 문구(Q100 "다음 라운드부터", Q107 "공간적 존재가 자격의 근거")는 (c)에 가장 가깝다. 그래도 결정은 소유자에게 맡긴다. 결정 전까지 C1은 `locked`와 `present_at_clear`만 기록한다(#213과 동일).
- 무엇이 "수령"인지는 **미결**(O-3). 현재 승인 보상은 공유 열쇠뿐이고 이것은 누구나 주울 수 있는 아이템이다. 개인 수령 이력을 쓸 승인된 개인 보상은 아직 없다. C1은 스키마와 API만 두고 수령 기록을 생성하지 않는다.

### 9.3 Vault 보존

컨트롤러와 장부는 Vault 블록·블록 엔티티(`rewarded_players` 등)를 읽거나 쓰지 않는다. Vault는 7개(일반 6 + 중앙 Ominous 1) 모두 바닐라 독립 개방을 유지하며 웨이브 잠금이 없다(I9). 장부의 수령 기록은 Vault 개방과 무관하다.

### 9.4 기록 삭제 금지

- 장부 항목은 추가만 한다.
- 다음 시험 시작은 활성 상태만 초기화하고 장부는 건드리지 않는다.
- 아레나 등록 해제는 장부가 비어 있지 않으면 거부한다. 강제 해제가 필요하면 장부를 같은 `instance_id`의 보관 목록으로 옮긴다.
- 보존 기간 정책은 미결이다(O-6). 기본값은 무기한 보존이다. 시험당 최대 6건이라 크기 위험은 낮다.

## 13. 미해결 사항과 위험

미해결(소유자 결정 필요):

- **O-1** Q111–Q113의 승인 원문이 저장소에 없다. 현행 권위에 원문을 기록해야 한다. 이 문서의 해석(§6.4, §8.4, §9)이 원문과 일치하는지 확인이 필요하다.
- **O-2** 개인 보상 자격 판정 기준(§9.2의 a–d 중 선택, 또는 다른 기준).
- **O-3** "수령"의 정의. 공유 열쇠 줍기를 개인 수령으로 기록하는가, 아니면 수령 이력은 향후 개인 보상 전용인가.
- **O-4** 라운드나 시험 전체의 제한 시간이 의도된 것인가. 권위에는 없으며, 이 설계는 60초 만료 두 가지만 "시간 초과"로 다룬다.
- **O-5** R3 역할 분류(2026-10-29 승인)를 Wave15 현행 권위에 동기화(현재는 PR #213 브랜치에만 있음).
- **O-6** 장부 보존 기간(기본: 무기한).

위험:

- **R-1** 평화로움 난이도에서는 몬스터가 즉시 제거되어 재소환이 반복된다. 라운드가 끝나지 않고 부재 60초에서만 정리된다.
- **R-2** 크래시 시 열쇠가 손실될 수 있다(최대 1회 정책). 정상 종료와 자동 저장에서는 발생하지 않는다.
- **R-3** 크리에이티브·관전자를 존재로 세지 않는다(바닐라 관례 추정, 확인 권장).
- **R-4** 플레이어가 구역에 남아 있는 동안 몹이 미로드 청크로 이동하면 라운드가 정체된다(손실·중복은 없음).
- **R-5** PR #211과 텍스트 병합 충돌이 예상된다(§1).
- **R-6** GameTest 서버는 실시간 속도와 무관하게 틱을 돌릴 수 있어, 무인 구간이 있는 재시작 테스트는 부재 유예 만료를 정상 결과로 허용해야 한다(#213에서 확인).
