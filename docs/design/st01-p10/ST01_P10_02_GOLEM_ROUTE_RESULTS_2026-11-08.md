# ST-01 P10 — 금 골렘 경로별 이동 결과 (산출물 2)

상태: **실제 서버(GameTest)에서 측정 완료.** 대상은 P9의 소형 금 골렘(`GoldGuideGolem`, scale 0.5, 충돌 상자 0.7×1.35, 속도 속성 0.25, 별도 엔티티, 바닐라 아이언 골렘 모델 재사용 — **최종 운영 사양이 아니라 검증 후보**)이며 **운영 코드는 변경하지 않았다.** 골렘 탐색 목표는 P9의 PROPOSED 정지 칸(Z2, 앵커 +(±10, −2, +3))이다. 원자료: `data/suite/route_trials_base.csv`, `data/solo/route_trials_base.csv`, 집계표 `generated/p10_measurement_tables.md`.

## 1. 측정 방법

- 픽스처: 산출물 1의 실제 왕실 묘실(동·서 각각 별도 배치). 골렘은 `configureGuide(tomb, stop)`만 설정(리더 없음 → 대기 없이 곧바로 이동)한 채 운영 클래스 그대로 생성. 동시 시험 골렘끼리는 스코어보드 팀 `collisionRule=NEVER`로 서로 밀지 않게 했다(측정 간섭 제거).
- 출발점(홀 중심 기준 (u 동+, v 남+); 서쪽 픽스처는 u를 반전해 이름의 의미 유지): `BOSS_S`(0,+6, P9 기본 생성 칸), `BOSS_N`(0,−6), `BOSS_E`(+6,0), `BOSS_W`(−6,0) — P3 보스 출현 후보; `DOOR_IN`(0,−15, 문 바로 안쪽), `CORRIDOR_OUT`(0,−21, **문 밖 3×3 통로 안**), `NW_CORNER`(−15,−15, 가장 먼 모서리), `OBELISK_N`(0,−3, 오벨리스크 기단 북쪽 바로 옆), `DAIS_FRONT`(0,+8, 제단 앞).
- 각 출발점 × 동/서 × **30회**(= 9 × 2 × 30 = **540회**). 회차마다 칸 안 무작위 위치(±0.3) + 무작위 방향, 3틱 간격 투입(시드 고정). 도착 시간은 "착지한 상태로 정지 칸 중심에서 1.5 이내(P9 TEST 반경)에 처음 들어온 틱"(생성 후 틱). 도착 후 80틱을 더 추적해 정지·미세 이동·덮개와의 거리를 쟀다.
- 환경: Temurin JDK 25.0.5, Minecraft 26.3, Fabric Loom 1.17.21, 헤드리스 GameTest 서버; 같은 서버에서 다른 P10 시험이 동시에 돌았을 때 평균 서버 틱 6.9–12.2 ms(중앙 7.5 ms).

## 4. 도착 후 거동 (O-4와 직결)

| 접근 | 정지 위치 | 덮개와 몸체 사이 간격 | 도착(r=1.5) 이후 이동 |
| --- | --- | --- | --- |
| 서쪽에서(BOSS_S/N/W, NW_CORNER, DAIS_FRONT) | 정지 칸 중심에서 서쪽 1.21 | **2.27–2.36 칸** | 최대 0.30칸 |
| 동쪽 통로(BOSS_E, DOOR_IN, CORRIDOR_OUT, OBELISK_N) | 정지 칸 중심에서 동쪽 0.87, 남쪽 0.27 | **최소 0.14, 정지 시 0.50–0.61 칸** | 최대 **1.78칸** |

골렘은 정지 칸 정확히 위가 아니라 **한 칸 가까이 앞에서** 멈춘다(경로 허용 오차 1: `moveTo`가 목표 1칸 이내에서 경로를 끝냄). 따라서 "정지 칸 + 반경"으로 만든 도착 영역과 실제 정지 위치는 접근 방향에 따라 달라진다. 자세한 내용과 후보는 산출물 6.

## 5. 한계

- 모든 시행이 같은 칸에서 출발하므로 **독립 표본이 아니다**. 도착 시간 분산(최대 약 ±10틱)은 출발 위치 지터와 방향에서만 나온다. 이 지오메트리·이 설정에서의 결정적 거동 확인이며 일반적 "안정성 보증"이 아니다.
- 경로 안내 대상(플레이어)을 두지 않은 순수 이동이다. 플레이어 동행·대기 상호작용은 산출물 3·5의 전체 파이프라인 측정을 본다.
- 실제 플레이어 접속, 클라이언트 렌더링, 실제 입력은 없다. **LIVE VALIDATION PENDING.**
