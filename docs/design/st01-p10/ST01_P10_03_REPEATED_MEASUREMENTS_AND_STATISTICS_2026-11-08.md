# ST-01 P10 — 반복 측정 데이터와 통계 (산출물 3)

상태: **측정 완료. 소수의 성공 사례로 안정성을 주장하지 않기 위해 표본 수·환경·독립성 한계를 함께 적는다.** 모든 원자료는 `data/` 아래 CSV이고 집계는 `tools/st01-p10/analyze.py`(재현 명령은 §6)가 만든다.

## 1. 환경
- Temurin JDK 25.0.5 · Minecraft 26.3 · Fabric Loom 1.17.21 · 헤드리스 GameTest 서버(`./gradlew runGameTest`), 컨테이너 한 대(코어 수·메모리는 고정하지 않음).
- 서버 평균 틱: 단독 실행 약 3 ms, P10 시험을 동시에 돌린 실행 6.9–12.2 ms(중앙 7.5), 부하 시험 64/154/254 ms.
- 운영 코드(`GoldGuideGolem`, `EntranceCore`, `McPorts`, `SecretEntranceRuntime`)는 P9 그대로. 시험이 바꾼 것은 생성된 엔티티의 속성 값뿐이다.
- **실제 플레이어 접속 없음.** 참가자는 모의 서버 플레이어이며 시험이 위치를 직접 옮긴다.

### 3.1 결과 요약
- **540/540 도착**, 경로탐색 실패 0, 타임아웃(1500틱) 0, 낙하 0, 엔티티 제거 0.
- 도착 시간의 시행 간 폭은 최대 약 17틱(BOSS_N 216–233), 대부분 ≤ 2틱. 큰 폭은 출발 칸 안의 무작위 위치가 경로 선택에 닿는 세 출발점(BOSS_S σ 3.3, BOSS_N σ 2.7, DAIS_FRONT σ 9.1)에서만 나타났다.
- 첫 경로 생성까지 시작 지연: 540/540 모두 20–21틱.
- 도착 전 연속 정지(경로가 끝난 뒤 다음 재탐색을 기다림): 중앙 4, p95 12, 최대 14틱. 시행의 12%(67/540)가 10틱을 넘는 정지를 겪었다. 도착 전 경로가 `null`이 된 틱은 시행당 평균 약 2.0틱.

## 4. 재현성·독립성에 대한 정직한 평가
- **결정적 시뮬레이션이다.** 같은 칸에서 같은 설정으로 출발하므로 시행 사이의 변동은 위치 지터(±0.3칸)와 방향뿐이다. 따라서 540회는 540개의 독립 표본이 아니다. "실패율 0/540"은 "이 기하·이 설정에서 우연히 실패하지 않았다"가 아니라 "이 입력 공간에서 경로탐색이 모든 지터에서 일관되게 성공한다"는 뜻에 더 가깝고, 그 이상의 일반화(다른 기하, 다른 엔티티 간섭, 실제 플레이어 이동)는 이 데이터로 주장하지 않는다.
- 단독 실행(270)과 P10 시험 동시 실행(E 270)을 비교하면 출발점별 [최소, 최대]가 같거나 ±1틱 — 이웃 시험과의 동시 실행 자체는 결과를 바꾸지 않았다.
- 동·서: 같은 입력에서 도착 틱 차이 ≤ 1.5틱, 정지 위치 거울 오차 ≤ 0.01칸.
- 서버 틱을 5배(254 ms) 늘려도 틱 단위 도착 시간 불변(산출물 5 §3).

## 5. 이 데이터가 말해 주지 못하는 것
- 실제 플레이어(이동 입력·충돌·지연·접속 끊김)와 클라이언트 동기화.
- 월드젠으로 놓인 구조물 외곽의 지형·광원·몹 스폰 간섭(O-14 미구현).
- 같은 서버에서 보스와 골렘 외의 다른 엔티티가 많은 상황(대규모 전투).
