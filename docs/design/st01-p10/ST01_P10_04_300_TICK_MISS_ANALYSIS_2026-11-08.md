# ST-01 P10 — 300틱 미도착 원인 분석 (산출물 4)

상태: **원인 확정(시험 하니스 결함) + 재현 + 경쟁 가설 기각.** 이번 조사는 운영 코드를 바꾸지 않았다. 운영 대기 시간(O-1)은 산출물 5에서 후보로만 제시한다.

## 1. P9에서 관찰된 현상
- 단독 시험: 약 113틱에 도착.
- 전체 스위트: TEST-ONLY 대체 타이머 300틱 안에 도착하지 못한 사례 1회 → 타이머를 600틱으로 올린 뒤 통과.

## 2. 이번에 확인한 사실 (결과 요약)

1. **전체 스위트에서 실패가 600틱 타이머로도 재현됐다.** 이번 전체 실행(타이머 600틱, P9 코드 그대로)에서 `secret_entrance_game_tests_gold_golem_leads_to_the_stop_point_and_opens_the_cover_exactly_once`가 실패했다.
   `no arrival by tick 1300: state=FALLBACK_OPEN remaining=0 golems=1 pos=(…2292699.26, 14.0, …2891440.26) stop=(…2292700, 14, …2891440) leader=<참가자> lead=(…, 2칸 뒤) navDone=true ground=true`
   → 골렘은 **정지 지점에 서 있고(거리 0.75 이내), 리더가 옆에 있으며, 경로도 끝났는데** 입구 상태는 `ENTRANCE_OPEN`이 아니라 `FALLBACK_OPEN`이다. 타이머를 600으로 올린 것은 원인 해결이 아니었다(상태가 늦게 `FALLBACK_OPEN`이 될 뿐).
2. **같은 증상이 결정적으로 재현된다.** 실제 묘실 픽스처에서 안내 도중 `SecretEntranceRuntime.forgetLiveState()`를 호출하면(시험 4회: 골렘 등장 후 3·20·60·120틱) 4/4 모두 골렘은 **154–155틱에 정지 지점에 도착**했지만 입구는 **601틱(대체 타이머)에 `FALLBACK_OPEN`** 으로 열렸다("도착했으나 감지 못함"). 대조군(`forgetLiveState` 없음, 참가자 표본 64회)은 64/64 정상 `ENTRANCE_OPEN`이다.
3. **P9 시험 코드가 이를 일으킨다.** `SecretEntranceGameTests.buildArena()`가 아레나를 만들 때마다 `SecretEntranceRuntime.forgetLiveState()`(프로세스 전역 `LIVE` 맵 전체 삭제)를 호출한다(P9 시험 파일 원본 84행). 같은 배치에서 늦게 시작하는 다른 P9 시험이 아레나를 만드는 순간, 이미 안내 중인 시험의 `EntranceCore`가 지워지고 다음 틱에 `Saved(state, remaining, coverApplied)`로만 복원된다. `guide`는 복원되지 않으므로(`respawnAfterRestart` 기본 꺼짐, 골렘은 `noSave`) `pollArrival()`의 조건(`guide != null`)이 영원히 거짓이 되고, 입구는 대체 타이머로만 열린다. 전체 스위트에서는 한 배치의 시험들이 수십 초에 걸쳐 차례로 시작되므로(이번 실행: 배치 시작 08:15:29, 골렘 시험의 안내 시작 08:15:52) 이 겹침이 발생한다. 필터로 P9 시험 17개만 돌리면 모두 같은 틱에 시작하므로 발생하지 않는다.
4. 운영 코드에서는 `forgetLiveState()`를 호출하는 곳이 없다(`SERVER_STOPPED`에서 `LIVE.clear()`만). 즉 **운영 입구 로직의 결함이 아니라 시험 간 전역 상태 간섭**이다. 다만 서버 재시작 시 같은 상황(안내 중 골렘 소실)은 설계대로 대체 타이머로 처리된다.

### 2.1 계측 실행(임시, 커밋하지 않음)
`forgetLiveState()`에 호출자·시각·보유 코어 상태를 출력하는 로그를 임시로 넣고(P10 시험은 제외) P9 포함 전체 스위트를 한 번 실행했다(기본 544개 시험, 약 4.5분). 결과:

| 시각 | 호출자 | 지워진 코어 |
| --- | --- | --- |
| 08:38:38 – 08:38:43 | `SecretEntranceGameTests.buildArena:84` × 17회 (P9 시험 17개가 시작할 때마다) | 첫 호출에서 저장된 인스턴스 437개 로드분, 이후 0 — 이 실행에서는 골렘 시험의 안내 시작(08:38:44) **이전에** 모두 끝나 간섭 없음 → 골렘 시험은 112틱에 통과 |
| **08:38:57** | `openStateSurvivesLiveStateLoss…` (P9 시험 자신, 2회) | **`GOLEM_GUIDING` 상태의 다른 시험 코어 2개를 포함해 454개 삭제** |

즉 (1) 수정하지 않은 전체 스위트에서 **안내 중인 다른 시험의 코어가 실제로 지워지고 있다**(08:38:57의 2개), (2) 어떤 시험이 피해를 보는지는 시험 시작 순서와 소요 시간의 겹침에 달려 있어 실행마다 다르다(이번 실행은 골렘 도착 시험이 피해를 보지 않았고, 앞선 실행에서는 보았다). 이 실행의 전체 결과는 Colosseum 13개 실패만 있고 ST-01 시험은 모두 통과했다.

(참고) 이 실행의 첫 호출에서 코어 437개가 보였다: 시험 월드가 실행 사이에 유지되어 이전 실행의 입구 인스턴스가 `SecretEntranceData`에 남아 있기 때문이다. `SecretEntranceRuntime.tick()`은 등록된 모든 인스턴스를 매 틱 돈다. 이번 측정에서 평균 서버 틱은 2–10 ms 수준이어서 문제는 아니었지만, 운영에서 인스턴스 수가 크게 늘면 OPEN 인스턴스도 매 틱 재확인하는 구조(O(N))라는 점은 기록해 둔다(범위 밖 관찰).

## 4. 600틱 상향이 왜 "통과한 것처럼" 보였나
간섭이 일어나는 쪽이 `FALLBACK_OPEN`이 된다는 점은 타이머가 300이든 600이든 같다. 간섭은 시험 시작 순서(이번에 겹치느냐)에 달려 있어 실행마다 다르다. 즉 600으로 올린 뒤의 통과는 **간섭이 우연히 없었던 실행**일 가능성이 높고, 실제로 이번 실행처럼 600에서도 실패한다.

## 5. 수정 후보 (시험 전용 변경만; 승인 필요 없음, 운영 코드 무변경)
| 후보 | 내용 | 효과 |
| --- | --- | --- |
| F1 | `buildArena`의 `forgetLiveState()` 호출 제거 — 새 아레나의 앵커는 `LIVE`에 없으므로 필요 없음 | 간섭의 주된 원인 제거 |
| F2 | 의도적으로 라이브 상태를 지우는 시험(`openStateSurvivesLiveStateLoss…`)을 별도 `environment`(= 별도 배치)로 분리 | 그 시험이 다른 시험을 지우지 않게 격리 |
| F3 | (진단 개선) 실패 메시지에 "골렘이 정지 지점에 서 있는데 상태가 열리지 않음"을 별도 표시 | 같은 증상을 "미도착"으로 오진하지 않음 |

**적용:** F1·F2를 이번 브랜치의 P9 시험(`SecretEntranceGameTests`)에 시험 전용 최소 변경으로 적용했다(운영 코드 무변경, 시험 기대값 무변경). 적용 후 결과: P9 필터 실행 17/17, 최종 HEAD 전체 스위트 3회에서 골렘 도착 시험 3/3 통과(도착 112틱). 다만 간섭은 시작 순서에 의존하는 간헐 현상이므로 **통과 횟수만으로 해결을 증명하지 않는다** — 증명은 (1) 호출자 계측으로 라이브 상태 삭제의 출처가 `buildArena`와 손실 시험 둘뿐임을 확인한 것, (2) 그 둘을 제거/격리한 것, (3) 같은 증상을 결정적으로 재현하는 `flowLiveStateLossWhileGuiding`(별도 환경에서 항상 통과하도록 기대값을 '대체 개방'으로 명시)이 회귀 감시를 한다는 점에 있다.

## 6. 정상 도착 시간 분포와 실패 사례의 분리 (O-1과의 관계)
- 정상 도착: BOSS_S 146–155틱, 먼 출발점 295–350틱, 참가자 동행 표본 149–404틱.
- 실패 사례(간섭): 도착은 정상(154–155틱)인데 **감지 불능**이라 601틱에 대체 개방.
- 두 가지를 섞으면 "정상 도착이 느리다"고 오해해 대체 개방 시간을 불필요하게 늘리게 된다. 따라서 **300틱 실패는 O-1 값을 정하는 근거로 쓰면 안 된다**(산출물 5의 후보는 정상 도착 분포와 참가자 거동에서 도출했다).
