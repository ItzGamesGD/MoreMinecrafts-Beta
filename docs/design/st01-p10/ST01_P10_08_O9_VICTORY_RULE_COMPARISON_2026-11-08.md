# ST-01 P10 — O-9 승리 판정 방식 비교 (산출물 8)

상태: **비교 분석 문서. 운영 기본 규칙은 변경하지 않았다.** 현재 운영 규칙은 P9가 승인·구현한 **방식 A**(수치 없는 구조 최소 규칙: 마지막 공격이 플레이어에게 귀속되어야 승리)이다. 방식 B의 피해 비율·시간 창은 **테스트 후보로만** 썼으며 어떤 값도 승인 아님이다. 규칙 변경에는 사용자 승인이 필요하다.

## 1. 비교 대상

| | 규칙 | 필요한 수치 | 현재 상태 |
| --- | --- | --- | --- |
| **A** | 마지막 공격(치명타)이 플레이어(투사체 주인·소유 엔티티 주인 포함)에게 귀속되고 그 플레이어가 참여자일 때만 승리. 환경·다른 몹·관리자 `/kill`은 승리 아님 | 없음 | **운영 기본값(P9)** |
| **B** | 플레이어 참여가 충분하면(총 플레이어 피해가 최대 체력의 `minShare` 이상이고, 마지막 플레이어 피해 이후 `window` 틱 이내) 치명타가 환경 피해·다른 몹이어도 승리. 관리자 `/kill`은 어느 쪽이든 승리 아님 | `minShare`, `window` (**미승인**) | `TombVictoryPolicy.install(Params)`로만 활성(테스트 전용) |

시나리오 14종을 **같은 `Participation` 판정 코드**에 A와 B(후보 12조합: 비율 0.25/0.5/0.75 × 창 100/200/600/1200틱)로 넣었다(`TombVictoryRuleComparisonTest`, 순수 로직 JUnit; 데이터 `data/o9_rule_matrix.csv`). 표의 "분석자 라벨"은 논의를 위한 **예시적 기대값이며 설계 권위가 아니다.**

## 2. 시나리오 행렬 (T = 승리, f = 승리 아님; B 열은 비율 0.25/0.5/0.75 각각에 대해 창 100·200·600·1200 순)

| ID | 상황 | 치명타 | 분석자 라벨 | A | B (0.25: 100/200/600/1200) | B (0.5: …) | B (0.75: …) |
| --- | --- | --- | --- | --- | --- | --- | --- |
| S01 | 플레이어가 전부 피해, 막타도 플레이어 | 플레이어 | 승리 | T | TTTT | TTTT | TTTT |
| S02 | 두 플레이어가 나눠 피해, 한 명이 막타 | 플레이어 | 승리 | T | TTTT | TTTT | TTTT |
| S03 | 플레이어 95%, 마지막 5%를 용암/공허가 | 환경 | 승리 | **f** | TTTT | TTTT | TTTT |
| S04 | 플레이어 95%, 적대 몹(해골 화살)이 막타 | 몹 | 승리 | **f** | TTTT | TTTT | TTTT |
| S05 | 플레이어 95%, 30초 뒤 환경 함정으로 사망 | 환경 | 승리 | **f** | ffTT | ffTT | ffTT |

| S07 | 플레이어 1% 접촉, 몹 분쇄기/다른 몹이 99% | 몹 | 비승리 | f | ffff | ffff | ffff |

| S09 | 플레이어 50% 후 이탈, 수 분 뒤 환경으로 사망 | 환경 | 비승리 | f | ffff | ffff | ffff |
| S10 | 플레이어 99% 후 다른 플레이어가 1% 막타 | 플레이어 | 승리 | T | TTTT | TTTT | TTTT |

| S12 | 참여 후 관리자 `/kill` | 명령 | 비승리 | f | ffff | ffff | ffff |
| S13 | 플레이어 피해 0, 환경/몹이 전부 | 환경 | 비승리 | f | ffff | ffff | ffff |

| | **승리 판정 수** | | | **5** | 7/7/8/8 | 7/7/8/8 | 7/7/8/8 |
| | **분석자 라벨과 일치(14 중)** | | | **9** | 13/13/14/14 | 13/13/14/14 | 13/13/14/14 |

관찰:
- 방식 A와 분석자 라벨이 어긋나는 곳은 S03·S04·S05·S11(플레이어가 거의 다 깎았는데 막타만 비귀속 → **정당한 승리가 무효**)과 S08(막타 도둑 → **약한 참여가 승리**) 5건이다.
- 방식 B(후보 값 전 범위)는 S08을 막고 S03·S04·S11을 살린다. 이 14개 시나리오에서는 **비율(0.25~0.75)이 결과를 바꾸지 않았다.** 창은 S05(마지막 플레이어 피해로부터 600틱 경과)에서만 결과를 갈랐다(≤200은 거절, ≥600은 허용). 즉 시나리오를 더 만들지 않는 한 비율 값은 이 데이터로 정할 수 없다.
- 14개 시나리오는 사람이 고른 예시이며 분포가 아니다. **표본이 아니라 사례 점검**이다.

## 3. 비교 분석

### 3.1 악용 가능성
| 항목 | A | B |
| --- | --- | --- |
| 환경 함정으로 보스를 깎고 마무리 | 막타가 환경이면 무효. 단 "플레이어가 막타만" 치는 변칙(S08)은 허용 → 함정으로 90%를 깎고 막타만 치는 방식이 가능 | 비율 하한이 막는다(S08). 반대로 하한만 넘기면(예: 25~50%) 나머지를 함정에 맡기는 방식이 가능해지고 창이 이를 제한(S05/S09) |
| 몹 분쇄기·다른 몹에게 맡기기 | 막타가 몹이면 무효 → 막음 | 하한+창을 넘기면 유효. 하한이 낮을수록 약한 참여로 통과 |
| 막타 도둑/늦은 합류 | **허용**(S08) — 참여자 목록에 이름만 올라도 성립 | 막음(비율) |
| 관리자 명령 | 무효 | 무효 |
| 막타 직전 접촉(1% 접촉) | 막타 플레이어면 유효 | 비율로 막음 |
| 의도적 방해(다른 파티가 막타를 빼앗음) | 같은 무덤이므로 참여자가 보상 이득을 공유(귀속 대상이 개인이 아님) | 동일 |

### 3.2 전투 경험
- A의 가장 큰 위험은 **정당한 승리가 무효**가 되는 경우다. 보스를 거의 다 처치한 뒤 화염·독·위더 등 **지속 피해**나 번개·폭발 등 **비귀속 피해**가 마지막 틱을 먹으면 보스는 죽었는데 상자가 열리지 않고 재도전해야 한다(`INVALID_DEATH` → 바인딩 해제 → 다시 도전 가능). 이 모드의 T2 원소 무기(화염 검 등)가 지속 피해를 주므로 가능성이 낮지 않다. §4의 피해원 측정이 어떤 피해원이 비귀속인지 보여 준다.
- B는 위 상황을 흡수하지만 "플레이어가 거의 아무것도 하지 않은 승리"를 수치로 걸러야 하며, 수치가 틀리면 이번에는 약한 참여가 통과한다.

### 3.3 구현 복잡도
| | A | B |
| --- | --- | --- |
| 코드 | 이미 구현·검증됨(구조 최소 규칙) | **이미 구현됨**(`Participation.judge`의 `Params` 분기, CR-2 추적). 새 코드 불필요, 수치 설치만 필요 |
| 수치/밸런스 | 없음 | 2개(비율·창) + 최대 체력/피해 감소/회복과의 상호작용 확인 필요 |
| 저장/재시작 | 참여 기록 영속화 이미 구현 | 동일 |
| 테스트 | 기존 보스·입구 테스트가 이미 통과(P9 기록) | 수치별 회귀 매트릭스 필요 |
| 운영 부담 | 낮음 | 수치 변경 시 보상 체감이 달라짐 |

### 3.4 보상 회귀 위험
- 어느 쪽도 보상 **양**을 바꾸지 않는다(유효 승리 시 최대 1회 드롭은 `markVictory` 멱등성으로 보장).
- A→B 전환은 "이전에 무효였던 사망(S03/S04/S05/S11)"이 유효가 되므로 **보상이 나오는 횟수가 늘어나는 방향**의 변화다. 반대로 S08류가 무효가 되어 줄어드는 경우도 있다. 기존 `defeated` 레거시 기록은 어느 방식에서도 자동으로 승리로 변환되지 않는다(P9 규칙 유지).
- B는 수치 선택에 따라 "함정 보조 처치"를 허용한다 → 난이도·보상 곡선에 영향. 보상 회귀 점검은 수치가 정해진 뒤에 해야 한다.

## 4. 피해원 귀속 측정

`RoyalTombSafetyGameTests.victoryRuleDamageSourceAttribution`이 피해원별로 `TombVictoryPolicy.classify`와 `attributedPlayer`를 측정했다(데이터 `data/suite/damage_source_attribution.csv`).

| 피해원 | `classify` | 플레이어 귀속 |
| --- | --- | --- |
| 플레이어 근접 · 플레이어가 쏜 화살 · 철퇴 | PLAYER | 예 |
| 플레이어가 일으킨 폭발(`explosion(null, player)`) · 플레이어에게 되돌려진 가시 | PLAYER | 예 |
| 적대 몹 근접(좀비) | MOB | 아니오 |
| 주인 없는 폭발 | ENVIRONMENT | 아니오 |
| **불붙음(`onFire`) — 화염 검/불 속성 이후의 지속 피해** · 불 속(`inFire`) · 용암 | ENVIRONMENT | **아니오** |
| **마법(독·즉시 피해 물약)** · **위더 효과** · 번개(원인 없음) | ENVIRONMENT | **아니오** |
| 낙하 · 선인장 · 동결 · 익사 · 공허 | ENVIRONMENT | 아니오 |
| `/kill` (`genericKill`) | COMMAND_KILL | 아니오 |

즉 방식 A에서 보스가 **플레이어가 붙인 불·독·위더의 마지막 틱**에 죽으면 환경 사망으로 분류되어 무효가 된다(S03/S05의 현실적 원인). 이 모드의 T2 원소 무기(화염 검 등)가 실제로 어떤 피해원/효과를 쓰는지는 이번에 측정하지 않았다 — 확인이 필요한 위험이다.

## 5. 선택지와 권장

| 선택지 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A 유지** | 현재 P9 규칙 그대로 | 수치 없음, 이미 검증됨, 악용 면이 좁음(함정 보조 불가) | 지속/비귀속 피해 마무리 시 정당한 승리가 무효 |
| **A + 귀속 보강(C)** | A를 유지하되 플레이어가 건 지속 피해(불·독·위더 등)와 소유 엔티티·폭발 등 **원인이 플레이어인 피해원의 귀속**을 늘림(수치 불필요) | 위의 불공정을 피해원 단위로 줄임, 환경 함정 보조는 계속 불허 | 피해원 목록 설계 필요(상태 효과 시전자 추적 등) — **새 설계 결정** |
| **B** | 위 표의 `minShare`/`window` 설치 | 정당한 승리 흡수 | 함정 보조 허용 범위가 수치에 의존, 수치 미승인 |

**권장(제안, 승인 아님): A 유지 + 사용자가 원하면 C를 별도 설계 과제로.** 이유: (1) B의 두 수치는 이번 데이터로 정해지지 않는다(비율은 결과 불변, 창은 단일 시나리오에만 반응). (2) A는 수치가 필요 없고 이미 운영 가능하다. (3) A의 실제 약점은 "비귀속 피해원 마무리"이며 이는 수치가 아니라 **귀속 범위의 설계 결정**이다. B를 택한다면 후보 출발점은 비율 0.5, 창 600틱(= S05를 허용하고 S08·S09를 막는 가장 단순한 조합)이지만 이는 승인 아닌 테스트 후보이다.

## 6. 변경 없음 확인
- `TombVictoryPolicy`/`TombGuardian*` 운영 코드 수정 없음. 비교는 `Params`를 시나리오별로 설치했다가 `install(null)`로 되돌리는 단위 테스트에서만 수행했다.
- 운영 기본값 `TombVictoryPolicy.installed() == null`이 유지됨을 단위 테스트로 확인(`ruleAIsTheShippedDefaultAndNeedsNoNumbers`).
