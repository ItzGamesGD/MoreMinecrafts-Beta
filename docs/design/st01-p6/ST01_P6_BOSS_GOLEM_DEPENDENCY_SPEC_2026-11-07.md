# ST-01 P6 — 보스·골렘 연계 의존성 명세 (2026-11-07)

상태: **의존성 조사 / 구현 승인 아님.** 저장소 코드는 읽기만 했고 수정하지 않았다. 정적 설계 검증과 런타임 검증을 분리한다. BOSS-R1은 종결하지 않는다.

## 1. 기존 구현이 제공하는 것 (`src/main/java/.../boss/`)

| 항목 | 위치 | 내용 |
| --- | --- | --- |
| 조우 진입점 | `TombGuardianEncounters.onRoyalChestInteraction(level, tombAnchor, spawnPos, …)` | 멱등. `tombAnchor`=왕실 상자 위치(의도), `spawnPos`=구조물이 사전 검증한 등장 지점 |
| 상자 봉인 질의 | `isRoyalChestSealed(level, tombAnchor)` | 처치 전까지 true |
| 처치 이벤트 | `Event<Defeated> DEFEATED` (`onDefeated(level, tombAnchor, killer)`) | 처치당 1회. 영속 기록(재접속·재시작 유지) |
| 종료/재시도 | `endEncounter`, 소멸 시 재시도 | 처치 전 소멸한 조우는 다음 상호작용에서 재시작 |
| 수치 | `TombGuardianTuning` | 보스 높이 2.9×1.5=4.35, 충격파 반경 6.0, 석상 높이 4.0 등 |
| 블록 변경 | 없음 | `setBlock/destroyBlock/explode` 호출 0건(바닥 읽기만) |

## 2. 구현이 없는 것

| 항목 | 상태 |
| --- | --- |
| `DEFEATED` 구독자 | 저장소에 없음 → 골렘 등장·비밀 입구 개방은 신규 구독자 필요 |
| 금 골렘 안내 엔티티 | 없음(권위: 보스와 분리된 안내 엔티티, 사망 처리 변경 금지) |
| 구조물 측 왕실 상자 블록/상호작용 | 없음(구조물 자체가 없음) |
| 등장 지점·앵커 좌표 | 미정(P3-F4: S 5.0 / E·W 12.5 / N 17.0 후보, 모두 PROPOSED) |

## 3. 구조물이 공급해야 하는 입력

1. `tombAnchor`: 왕실 주 상자 좌표 — P3 `CHEST_PRIMARY` (동쪽 모델 기준 홀 중심 X −21, 상자 Y −20, Z 33 / 서쪽은 X 거울). *단 상자 크기(1×1/2×1)는 P3-F6 UNVERIFIED.*
2. `spawnPos`: 등장 지점 — P3-F4 후보 중 하나(미정).
3. 홀 입구/상자 접근 높이: BOSS-R1(문턱 3·접근로 4 < 보스 4.35)이 실전 검증 대기이므로 변경하지 않았다.

## 4. 정적 검증 결과 (설계 수준)

- CLOSED 홀은 P3 모델과 복셀 동일(P5.K1). 따라서 P3에서 검증된 전투 공간이 보스 전투 중 변하지 않는다.
- OPEN 절개는 홀 후방 안쪽 모서리의 12칸이다. 등장 후보에서 가장 가까운 절개 칸까지 수평 거리: S 13.4, E 13.4, N 21.6, W 21.6 (BF1, 측정값; 충격파 반경 6.0 밖. 전투 의미는 UNVERIFIED).
- 골렘 경로 프록시(BF1): 왕실 상자 접근점 → 숨은 계단 입구 18걸음, 입구 → 거대 상자 앞 42걸음, 경로 머리 공간 ≥2. 소형 골렘의 실제 크기·경로탐색 가능 여부는 UNVERIFIED.

## 5. 런타임 검증이 필요한 항목 (UNVERIFIED, 이번에 검증하지 않음)

보스 AI/충격파/석상 분출과 홀 기하의 상호작용(BOSS-R1 포함), 골렘 경로탐색·대기·재시도, 안내 실패 시 비잠금 접근, 처치 후 재접속에서의 비밀 입구 상태 영속, 반복 승리 처리.
