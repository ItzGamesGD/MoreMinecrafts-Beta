## 건축 구성

기단의 석재 코어와 외부 상승로가 본체에 연결된다. 내부 지름은 약26을 유지하고 외벽을 얇게 조정해 계단 공간을 넓혔다. 외벽에는 채광 개구부·벽기둥·수평 띠·석재 프레임이 있으며, 출입 관문에는 이중 프레임/아치·단계별 기하 문양·부분 반블록 차양·조명을 배치했다.

외부 다섯 상승 구간은 기단부터 성소까지 이어진다. 아케이드 기둥70개는 3×3 기단/주두와 모서리를 깎은 몸체, 계단 하부와 연결되는 코벨을 갖는다. 작은 베이는 반원형 격자 근사, 발코니의 넓은 베이는 위층 발코니 아래에 들어가는 낮은 아치다. 면 연결 래스터로 아치 조각이 공중에 따로 떨어지는 문제를 고쳤다. 반블록 디딤판의 점프 없는 상승을 사용한다.

남북 발코니는 각 전투층 상승 구간에2개씩 총8개다. 바닥9×5 내부에 난간을 제외한7×3을 확보하고, 중앙 접속·주변 난간·하부 받침·연결된 장식 아치·숨긴 조명을 넣었다. 기존 편측 개구부 대신 중앙 동선으로 진입한다. 수직 반복 배치로 바뀐 이유와 시각적 영향은 변경표에 기록했다.

각 전투층에 내부 기둥8개, 중앙 평탄 문양, 3×3 제단4개, 접근 반블록, 실제 시련 스포너4개, 실제 금고2개가 있다. 중앙 문양을 지름11로 줄여 전투/제단/금고 동선을 확보했다. 스포너 구성은 바닐라 좀비 normal/ominous, 금고는 trial_key와 바닐라 보상 loot table이다.

성소의12기둥을15° 회전시켜 정상 진입 축을 열었다. 12아치가 y79까지 올라가지만 지붕으로 연결하지 않는다. 중앙 청록 고리와 빛나는 작은 핵은 의도적으로 부유한다. 이 유물 이외의 석재는 면 연결 검사에서 본체와 연결되어 있다. 풍화는 수행하지 않았다.

### 실제 폭과 목표 폭

새 디딤판의 공칭 반경 띠는14.5..20.5(폭6)이다. 원 목표 폭4와 달리 복셀화 손실을 흡수하려고 바닥을 넓혔다. 단면의 물리적 빈 폭, 플레이어 중심 구간, 실제 보행 가능성은 별도로 계산했다.

| F1→F2 | 4.538706 | 331° | 21 |

기단·성소 접속부에서는 폭4 목표를 소폭 밑돈다. 기존3.265를 승인하거나 모든 곳에 폭4가 있다고 주장하지 않는다. .5° 표본의 각 반경 구간은 연속적으로 계산하지만 모든 각도 전역 최소의 수학적 인증은 아니다. 고정 발 높이의 중심 구간은 단차 경계에서0이 될 수 있으며, 발 높이를 바꿔 이동하는 실제 경로와 다르다.

기존246.75° 반례 각도도 새 점유로 재계산했다(`old_witness_regression.json`). 새 물리 폭은 기단/중간 구간5.441933, 마지막 구간4.353546이다. 옛 벽·기둥 위치를 그대로 정답으로 사용하지 않았다. 실제 동선 검증과 정적 분리 차선 결과가 이 폭 측정의 한계를 보완하지만 전역 폭 증명이나 실제 멀티플레이 시험을 대신하지 않는다.

## 실제 서버·클라이언트 검증

공식 Minecraft26.3 서버 SHA1 `33680f5f2ac32864d6d7cf5e56a705fdb3e05f4c`, Java25.0.4.1. 실제 클라이언트도 공식26.3, Xvfb1280×720, Vulkan llvmpipe/LLVM19 소프트웨어 렌더링으로 실행했다. 시험 월드는 vanilla flat, template offset `(1000,65,1000)`, 지면 상면65, localhost 전용이다.

`server_placement.json`: strict 배치 후 경계 상자 전체 **196,000좌표**를 공기까지 대조했다. 최종 불일치 **0**. 스포너의 정상적인 inactive→waiting_for_players 상태 전환은 좌표 오류와 구분했고 설정 NBT도 읽었다. 템플릿에 공기가 생략되므로 재배치 전 이전 후보를 비우도록 시험 절차를 수정했다. 이전1776개 잔여 블록 검출 기록은 `server_placement_stale_world.json`에 보존했다.

실제 주동선 보행은 `live_walk.json`, 8발코니 시험은 `live_balconies.json`, 낙하/상승 표본 감사는 `live_walk_audit.json`에 있다. 주동선은 초기 순간이동 이후 W키와 방향 회전만 사용해 기단에서 F1–F4 중앙과 성소 중앙까지 약163초에 도달했다. 마지막 외부 발코니 바닥5칸 복구 후에는 최종 점유에 대해 실제 주동선1292표본을 재생해 몸통 충돌0을 확인했다(`flat_and_trace.json`); 이 재생 자체는 새 클라이언트 주행이 아니다. 수정된 발코니들은 최종 후보에서 실제 재시험했다. 초기 성소 축 기둥에서 멈춘 기록과 발코니 아치 간섭 기록은 수정 전 파일로 분리했다.

최종 실제 발코니 시험은 8/8 진입·복귀 성공, 각3초 바깥 밀기 중 높이 유지 및 난간 차단을 확인했다. 최종 주동선 기록은163.29초, 5개 층 중앙 방문, 표본 간 최대상승.5/최대하강0이었다. 마지막 발코니 바닥5칸 복구는 주동선 기록 후 수행했으므로 주동선의 최종 점유 재생과 수정 발코니 실제 재시험을 구분해 기록했다.

`functional_smoke.json`: 보통 난이도에서 실제 플레이어를 시련 스포너가 등록했고 ACTIVE 상태·좀비12개를 확인했다(대표 스포너 total_mobs_spawned=3). 실제 클라이언트의 우클릭으로 금고가 시련 열쇠를 소비하고 rewarded_players를 기록했으며 주변 보상 아이템2개를 확인했다. 이는 대표 스포너/금고 상호작용 시험이며 전체 전투 캠페인·모든 금고·ominous 검증은 아니다.

실제 화면10장과 좌표·시각은 `screenshots/`, `captures.json`에 있다. 탑 정면·사선·올려다보기·아케이드·발코니·전투실·관문·성소·야간·원거리이며 전부 실제 게임 프레임이다. 개념 렌더나 생성 이미지로 대체하지 않았다.

## 발견 후 수정한 주요 문제

1. 기단 진입부의 기존 외측 난간을 실제 입구로 열고 측면 보호를 연결했다.
2. 포털 회전 경계에서 이웃 계단의 높이가 달라지는 면을 보호했다. 면 검사가 받침 위 잠재 보행을 놓치지 않도록 회귀 테스트도 수정했다.
3. 성소 축 기둥을 회전시켜 실제 직선 진입을 열었다.
4. 아치 높이 보간의 끝점 변수가 래스터 반복에서 덮이는 생성기 결함을 고쳤다.
5. 넓은 하층 아치 및 몰딩이 위층 발코니에 닿지 않도록 낮추고, 장식이 보행 바닥을 덮어써 높이를 바꾸지 못하도록 우선순위를 수정했다. 중앙 접속부의 연속 충돌 검사와 실제 진입·복귀를 다시 수행했다.
6. 떠 있는 조명·난간·발코니 아치·관문 조각을 연결했다.

## 남은 범위

- 사용자 시각 검토 전 DESIGN APPROVED로 표시하지 않는다.
- 모든 스포너의 전체 전투·보상 반복, ominous, 재시작, 여러 실제 플레이어 동시 교행/전투는 별도 검증 범위다. 단일 스포너/금고 smoke test는 수행한 범위만 기록한다.
- 층 완료 감지·영구 결계 해제·모드 특별 보상의 Java 로직과 월드젠 등록은 구현하지 않았다. 건축 앵커와 실제 바닐라 기능 블록을 제공하며 기존 게임 시스템은 변경하지 않았다.
- 제단·내부 이동·계단·발코니의 건축 동선 검증과 완전한 플레이 캠페인 통합 승인은 다르다.
- 자연섬은 생성하지 않는다. 문서의 배치 지면 조건을 지켜야 정상 진입이 연결된다.
