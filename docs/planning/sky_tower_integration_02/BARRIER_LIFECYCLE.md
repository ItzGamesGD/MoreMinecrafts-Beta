# 72칸 결계 lifecycle

승인 NBT는 바이트 불변. 로컬 x39..44,z27, y11..13/22..24/34..36/48..50. `SkyTowerLayout.Site.barrier(floor,cell)`은 cell0..17을 x우선·y3칸 순으로 배치하고 기존 원점/회전 변환을 사용한다. 4회전0/1/2/3은 none/cw90/180/ccw90이며 각 층18개·총72개다. 실제 셀은 `worldgen_audit`와 별도로01 동결 검사 및02 테스트에서 확인한다.

서버 ENDtick 매20tick에 등록된 같은 차원의 탑만 검사한다. 강제 청크 로드 없음. 층의18셀 중 블록 청크가 하나라도 미로드면 보류한다. 설치에는 바닐라 EntitySectionStorage의 실제 수평 조회 범위(셀 AABB의 x/z min−2..max+2)에 포함된 모든 청크의 블록 및 엔티티 저장 준비도 요구한다. 이웃 청크에 중심이 있는 몸체가 결계에 걸칠 수 있기 때문이다. 준비되지 않으면 강제 로드하지 않고 보류한다. 완료된 소유 벽의 제거는 엔티티를 가두지 않으므로 자체 블록 청크가 준비되면 진행한다. 미완료 층은 전 셀을 사전 검사하며 기존 비공기 블록·외부 barrier·BlockEntity·엔티티가 있으면 새 설치를 보류하고 충돌 로그를 남긴다. 플레이어/몹을 벽 안에 가두기 위해 밀거나 순간이동하지 않는다.

설치 성공한 셀만 SavedData의 층별18비트 `owned_barriers`로 소유한다. 완료4비트 quorum이 모이면 **소유하고 현재도 barrier인 셀만** 제거한다. 완료층에는 새 barrier를 설치하지 않는다. 완료층에 외부 블록이 남으면 보존하며 충돌로 기록한다. 미완료층의 다른 탑/차원에는 영향 없다.

LevelChunk의 성공한 실제 변경 RETURN에서 이전 barrier가 다른 블록으로 바뀌면 소유권을 즉시 해제한다. 삭제 후 외부 시스템/플레이어가 새 barrier를 놓아도 채택하지 않으므로 완료 시 이를 삭제하지 않는다. 단지 blockstate가 동일한 set 호출은 실제 교체가 아니며 ownership을 바꾸지 않는다.

저장은 기존 schema version1에 optional `owned_barriers:[0,0,0,0]`를 추가한다. 구버전 기록은 소유권0으로 읽고 기존 완료비트를 보존한다. 이미 완료된 구버전 층에는 결계를 새로 설치하지 않는다. 정상 save/stop/start와 청크 재로드에서 저장된 소유권·완료 상태로 재조정한다.

저장 실패/전원 차단으로 월드 barrier와 소유권 파일이 서로 다른 시점에 저장될 수 있는 창은 원자적으로 해결했다고 주장하지 않는다. 소유권 증거가 없는 barrier는 외부 블록으로 보존하고 충돌로 멈춘다. 반대로 소유 기록이 있으나 실제 블록이 다른 경우 소유권을 포기하고 그 블록은 보존한다. 자동으로 외부 barrier를 채택하거나 삭제하는 복구는 없다. 런타임 결계는 블록 보호·강제 복귀·가상 엔티티·추가 네트워크 시스템을 추가하지 않는다.

26.3 barrier는 WATERLOGGED 프로퍼티를 가진다. 설치한 건조 defaultBlockState와 **정확히 같은 상태**만 소유 대상으로 유지·제거한다. 외부에서 같은 barrier 타입의 waterlogged 상태만 바꿔도 성공한 변경 훅에서 소유권을 포기한다. 재시작 때 소유 기록이 남았지만 실제 상태가 기본값과 다르면 역시 포기하고 그 상태를 보존한다. 단순 타입 비교로 물 상태를 삭제하지 않는다. native waterlogged RED와 수정 후 네 번째 GameTest를 별도로 기록한다.
