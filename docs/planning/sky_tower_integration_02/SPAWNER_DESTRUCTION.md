# 필수 스포너 실제 제거와 진행

`SkyTowerBlockChangeMixin`은26.3 `LevelChunk.setBlockState(BlockPos,BlockState,int)`의 RETURN에서 반환된 실제 이전 상태와 변경 후 상태를 관찰한다. null/동일상태/클라이언트/서버 스레드 밖은 무시한다. 파괴 시도나 취소된 이벤트에는 chunk 변경이 없으므로 완료하지 않는다.

이전 블록이 trial_spawner이고 변경 후에는 trial_spawner가 아닐 때만 제거 증거다. 같은 spawner의 inactive→active→cooldown 상태 변경은 파괴가 아니다. 같은 차원·정확한 등록 필수 앵커를 찾아 아직 미완료이면 완료비트와 `destroyed_spawners` 원인비트를 함께 저장한다. 플레이어 파괴뿐 아니라 실제 블록 교체를 일으킨 명령·폭발/외부 서버 변경도 이 경로에서 관찰한다. 스포너가 '안 보인다'는 사후 추측만으로 완료하지 않는다. 훅 밖에서 오프라인 NBT를 수정한 경우의 원인은 확정할 수 없어 미검증이다.

정상 완료는 기존 TrialSpawner COOLDOWN 관찰을 유지한다. 완료 원인은 처음 기록된 증거가 유지된다. 파괴 후 cooldown/중복 파괴, 정상 완료 후 파괴, 여러 플레이어의 같은 실제 제거 등은 이미 설정된 비트에서 no-op이다. 스포너를 다시 설치해도 진행을 초기화하지 않는다. 원인 비트는 완료비트의 부분집합이어야 하며 손상된 입력은 기존 quarantine으로 격리한다.

구버전 schema1에는 파괴 원인이 없었으므로 optional destroyed_spawners 기본0, 기존 완료는 그대로다. 0을 '과거 모든 정상 보상을 실제 수령했다'는 지급 장부로 해석하지 않는다. 단지 파괴 완료로 새로 기록된 증거가 없다는 뜻이다.

**추가 보상 없음**: 제거 관찰자는 아이템/열쇠/몹/금고를 생성하지 않고 바닐라 보상 함수도 호출하지 않는다. 정상 시련·금고의 바닐라 기록과 QuestVaultRewards 관찰은 그대로다. 스포너가 바닐라에서 이미 지급한 보상을 회수하거나 중복 지급하지 않는다. 층 완료는 원인과 무관하게 기존4개 quorum이고 영구·구조물 공유 상태다. 옥상 특별 보상/전체 완료 이벤트는 추가하지 않았다.
