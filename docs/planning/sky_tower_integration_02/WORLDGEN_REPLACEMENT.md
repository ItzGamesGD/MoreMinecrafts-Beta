# 기존 하늘섬 교체 감사 — Phase C 보류

## 2026-11-08 중심 배치 추가 좌표 증거

`island_overlap_probe.py`는 승인 NBT SHA-256을 고정하고 원점 `(-3,17,-3)`에서 탑과 섬의 비공기 블록 좌표를 대조한다. `island_overlap_probe.json`에 모든 겹침 좌표·블록 종류가 있다. snowy 198, meadow 220, forest 334, badlands 9, desert 4, rocky 11개다. 눈·나뭇잎·나무·풀·지형 블록이 포함된다. 이는 중심 배치의 template 좌표 중첩이며 실제 월드 생성 시 덮어쓰기 결과나 다른 배치의 불가능성 증명이 아니다.

국소 접속 후보의 평면 `x41..45,y16,z19..23` 25칸과 `x40..45,y17..18,z19..23` 머리 공간에는 여섯 섬 모두 비공기 블록이 없었다. 중심선에서는 예컨대 snowy에서 x39의 최상단이 y14이고 x40 이후 섬 블록이 없어 이 평면까지의 단차·지지 연결이 필요하다. 나머지 너비의 실제 지형, 전방 반블록과 보행, 충돌 및 네 회전은 검증하지 않았다. 이 후보는 적용·승인된 연결 설계가 아니며 25칸만 놓으면 문제가 해결된다는 뜻이 아니다. 단순 연결면 외에 탑과 기존 식생/지형의 직접 중첩도 별도로 해결해야 한다.

사용자가 기존 정책/구형 탑 교체를 승인했다. 새 빈도·섬 확대·건축 변경을 승인한 것으로 해석하지 않았다. **현재 생산 월드젠은 구형 탑을 계속 생성하며, 신규 탑 자동 등록은 구현하지 않았다.** 승인된 B 런타임은 수동 등록 구조물에서 작동한다. 자연 생성 교체·자동 등록 PASS가 아니다.

## 직접 치환이 불가능한 현재 슬롯

승인 탑은50×80×49, 중심축 로컬(24.5,24.5), 입구 반블록 로컬 x49,z22..26. 승인 NBT에는 incoming jigsaw가 없으므로 이름만 pool에 바꾸어도 연결되지 않는다.

중앙을 가까운 블록 좌표에 맞추고 기존 소켓 위에 놓는 진단 원점은 섬 로컬(-3,17,-3)이다. 그 경우 탑 AABB는(-3,17,-3)..(46,96,45), 기존 parent AABB는(0,0,0)..(42,73,42)이다. x/z와 상부가 벗어나 기존 내부 자식 슬롯에 들어가지 않는다. 탑 높이80은 기존 상부 여유58보다22블록 크다. 이는 **현재 중앙 슬롯·기존 경계 아래의 반례**이며, 설계 전체의 불가능성 증명이 아니다.

입구 반블록의 대응 위치는(46,17,21), 그 아래 지지면 조사 열은(46,y≤16,21)이다. 여섯 스타일 모두 해당 열의 섬 블록이0개였다. 기존 섬의 물리 반경19보다 입구 반경25가6블록 멀다. 바운드만 늘리는 해법은 지면 접속이나 섬에서 기단 진입을 검증하지 못한다. `worldgen_audit.json`은 실제 NBT 크기·socket·원점·정책 해시 및 각 스타일의 반례를 보존한다.

## 최소 변경 제안 — 미적용

1. **빈 메타데이터 경계만 확장**: 기존 섬의 물리 지형을 넓히지 않고, 중심 배치의 음수 좌표를 정규화하려면 x/z에3씩 이동한50×97×49 wrapper 경계가 필요하다. 기존43×74×43 대비 치수 +7/+23/+6. 기존 모든 지형·다른 콘텐츠의 상대 좌표는 유지하되 월드 원점을 보정할 생성 어댑터/래퍼가 필요하다. 승인 탑 payload는 그대로 두고 별도 연결 어댑터를 쓴다. 아직 자연 jigsaw 배치로 검증하지 않았다.
2. **기단 접속**: 외부 입구까지 최소6블록의 반경 부족을 해결해야 한다. 후보는 좁은 5칸 폭 접속대/부유 지지부 또는 탑을 국소 편심 배치하여 기존 지형에 입구를 맞추는 방식이다. 접속대의 실제 길이·높이는 스타일별 경사와 기단의 플레이어 충돌 상자로 다시 산출해야 한다. 단순 6×5=30블록 평판만으로 '완성' 판정하지 않는다. 외형/섬 플레이 영역에 변화가 있으므로 이번에 임의 적용하지 않았다.
3. **상부 높이**: 기존 WORLD_SURFACE_WG 투영 + 일반40..110/고산18..70 밴드와 dimension_padding4를 유지하면 높은 지형에서80블록 탑이 상한을 넘을 수 있다. 밴드를 임의로 낮추지 않았으며 후보별 자연 생성 성공률·청크 경계/주변 구조물 간섭 검증이 필요하다.

이 중 필요한 접속 형태/배치가 결정되면 새 candidate 리소스와 생성 완료/청크 로드 기반 지연 등록을 구현할 수 있다. 현재는 승인되지 않은 섬 재설계를 적용하거나 자연 생성에 맞지 않는 pool을 활성화하지 않고 **사용자 지시의 Phase C 중단 조건**을 따른다. 자동 등록도 생산 생성 위치/회전을 검증하지 못한 상태에서 좌표 추측으로 만들지 않았다.

`worldgen_fit.svg`는 실제 meadow NBT의 지형 투영·승인 탑의 기단·기존/신규 경계를 겹친 정적 감사 도면이다. Minecraft 스크린샷이나 적용된 접속 설계가 아니다.
